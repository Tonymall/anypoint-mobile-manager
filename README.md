# MuleOps — Anypoint Mobile Manager

A mobile companion app (iOS + Android) for managing MuleSoft Anypoint Platform: runtime manager, API manager, monitoring, alerts, and platform administration from your phone.

Built with Expo SDK 57 / React Native 0.86, TypeScript, Expo Router, TanStack Query, and Zustand. Distributed through the App Store and Google Play via EAS.

## Repository layout

| Path | Purpose |
|---|---|
| `app/` | Expo Router file-based routes (thin re-exports of screens) |
| `src/screens/` | Screen implementations, grouped by feature |
| `src/services/` | Anypoint API client layer (axios) |
| `src/stores/` | Zustand stores (auth store is persisted) |
| `src/hooks/queries/` | TanStack Query hooks |
| `backend/` | Thin Express backend (push relay, bug reports, remote config, lifecycle watch) — see `backend/README.md` |

Native projects (`ios/`, `android/`) are **not** committed — they are generated by Expo prebuild (CNG). All native configuration lives in `app.json`; never edit native folders directly.

## Branch model

- **`development`** — the main branch. **This is the production branch**: every App Store / Play Store release is built from it. `origin/HEAD` points here.
- Feature branches — branch off `development`, merge back via PR. CI (typecheck, lint, test, expo-doctor) runs on every PR.

## Getting started

```bash
npm ci
npm start          # Expo dev server
npm run ios        # iOS simulator
npm run android    # Android emulator
```

Copy `.env.example` to `.env` if you need to point at a non-default backend (`EXPO_PUBLIC_BACKEND_URL`).

### Quality checks

```bash
npm run typecheck
npm run lint
npm test
npx expo-doctor
```

## Releasing

Version source is **remote** (`appVersionSource: remote` in `eas.json`) — EAS manages build numbers; `version`/`runtimeVersion` in `app.json` are bumped manually per release.

1. Ensure `development` is green in CI.
2. Bump `expo.version` and `expo.runtimeVersion` in `app.json` (and `package.json` version).
   - `runtimeVersion` **must** change whenever native dependencies change (SDK upgrade, new native module); it fences OTA updates to compatible binaries.
3. Build: `eas build --profile production --platform all`
4. Submit: `eas submit --profile production --platform ios` (and `--platform android`)
5. OTA-only JS fixes between store releases: `eas update --channel production` — only safe when `runtimeVersion` matches the store binary.

Channels: `production` (store builds) and `beta` (`--profile beta`).
